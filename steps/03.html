3. Защита сервера

Прежде чем поселить ИИ, поставим крепкую дверь и хороший замок! 🔐

Зачем это нужно

Сервер постоянно доступен через интернет, поэтому его безопасность нельзя откладывать. Мы создадим отдельного пользователя, настроим вход по SSH-ключу, обновления и сетевой экран. Всё сделаем последовательно, чтобы случайно не потерять доступ.

Главное правило этого шага: не закрывай окно, где ты уже вошёл на сервер, пока не проверишь новый вход в отдельном окне. Тогда ты не потеряешь доступ.

1. Обновляем систему

apt update && apt -y upgrade

2. Создаём обычного пользователя

Работать от имени root опасно: он может всё и без вопросов. Создадим пользователя ai (имя любое):

adduser ai
usermod -aG sudo ai

3. Вход по SSH-ключу

Ключ — это как цифровой замок из двух частей. Одна часть остаётся у тебя, другая — на сервере. На своём компьютере (не на сервере) выполни:

ssh-keygen -t ed25519
ssh-copy-id ai@203.0.113.10

Если у тебя Windows, команды ssh-copy-id там нет. Вместо неё выполни в PowerShell одну длинную команду:

type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ai@203.0.113.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

Теперь открой новое окно терминала и проверь вход:

ssh ai@203.0.113.10

Если вошёл без пароля от сервера (мог попросить только пароль от ключа) — всё хорошо.

4. Отключаем вход по паролю и под root

Сначала убедись, что вход по ключу работает. Затем на сервере, уже под пользователем ai:

sudo nano /etc/ssh/sshd_config.d/00-hardening.conf

Имя файла начинается с 00- не случайно: настройки читаются по порядку, и первое значение побеждает. Так наша защита не перебьётся настройками хостинга. Впиши в файл две строки, сохрани (Ctrl+O, Enter) и выйди (Ctrl+X):

PasswordAuthentication no
PermitRootLogin no
sudo sshd -t && sudo systemctl reload ssh

Первая команда проверяет настройки, вторая применяет их. Снова проверь вход в новом окне.

5. Сетевой экран (ufw)

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status

Должно быть: статус active, и правило для OpenSSH разрешено.

6. Защита от подбора пароля (fail2ban)

sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
sudo fail2ban-client status

Fail2ban сам временно блокирует тех, кто часто ошибается при входе. Это отсекает большинство автоматических атак.

Что должно получиться

Сервер получит базовую защиту от распространённых угроз. Ты научишься безопаснее управлять им и поймёшь, почему нельзя публиковать пароли и секретные ключи.

Частые ошибки

  • Оставлять простой пароль
  • Отключать старый способ входа до проверки нового
  • Закрывать SSH-порт в сетевом экране без проверки доступа
